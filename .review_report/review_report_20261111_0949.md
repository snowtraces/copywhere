## 1. 需求与上下文

需求原文：

1. 「界面输入框，支持复制文件后 focus 状态直接粘贴传输」；
2. 「不要重新截图的提示，正常取消，静默处理」——附件按钮打开的文件选择器被用户取消时，
   不应弹出截图里的 `打开文件选择器失败: Invalid dialog call: Dialog.OpenFile failed:
   error getting selection: cancelled by user`。

根因（已核对依赖源码，非猜测）：

- `wails/v3@v3.1.0/pkg/application/messageprocessor_dialog.go:90-103` 把
  `PromptForMultipleSelection()` 返回的任何错误都包成 `Invalid dialog call`，
  而 `internal/go-common-file-dialog/cfd/hresult.go:8` 把 Win32 `ERROR_CANCELLED`
  映射为 `ErrorCancelled`（文案 `cancelled by user`）。即：**用户点取消 = 前端收到 error**，
  与 `dialogs.ts` 注释里"取消返回空列表"的约定不一致。
- 网页侧 `ClipboardEvent.clipboardData.files` 只有文件名、没有真实路径（浏览器安全边界），
  所以粘贴投送必须由 Go 端读系统剪贴板。

## 3. 五轴评审

### 3.1 正确性

- `PasteFiles` 的返回值语义自洽：`0` = 剪贴板里没有文件（静默、前端回退文本粘贴），
  `>0` = 已投送条目数，`error` = 有文件但发送失败（未配对/`stat` 失败/读剪贴板失败）。
  与 `SendFiles` 的既有校验（路径存在、已配对、未被鉴权拒绝）完全复用，没有新增判定分支。
- 前端粘贴判定顺序为「文本优先 → Files / 空类型接管」，避免了 `Excel/Word` 复制时
  剪贴板同时带位图预览（在 Chromium 里可能表现为 `Files` 类型）把文本粘贴吞掉。
- 取消识别覆盖两种情况：`throw`（当前 Wails 行为）与返回空列表/空字符串（依赖升级后的行为），
  两条路径都不会误发 `SendFiles`。
- `errors.Is(err, clip.ErrNoFiles)` 正确匹配 `clip` 包的哨兵错误；非 Windows 构建下
  `clip.ReadFiles` 返回占位错误，会走 `读取剪贴板文件失败` 分支（本应用仅支持 Windows，可接受）。
- 无 off-by-one / 空指针风险：`paths` 长度、`dt.types` 空数组均已前置判断。

### 3.2 可读性

- 注释解释的是「为什么」（Wails 把取消当错误、网页拿不到真实路径、文本优先的原因），
  而不是复述代码；与仓库既有中文注释风格一致。
- 命名 `PasteFiles` / `pasteFilesFromClipboard` / `isDialogCancelled` 表意明确，
  与 `SendFiles` / `pickFiles` 的既有命名形成对称。
- 无死代码、无兼容垫片、无 `// removed` 残留。

### 3.3 架构

- 复用既有链路：粘贴 = 取路径（`clip.ReadFiles`）→ `Service.SendFiles`，
  与拖放（`WindowFilesDropped`）、附件按钮（`SendFiles`）**同一个出口**，
  toast/时间线/进度/失败态零新增代码。
- 真实路径只在 Go 侧出现，前端不新增任何文件系统能力，模块边界没有被打破。
- 依赖方向未变（`wailsui` → `clip` 是既有下层包，`monitor` 已在用）。

### 3.4 安全

- 只读系统剪贴板、只向「已配对且未被鉴权拒绝」的节点投送，未新增写盘/写注册表/执行能力。
- 剪贴板内容视为不可信输入：路径经 `os.Stat` 校验后才进入发送，不可达路径被忽略并记日志，
  不会因伪造路径导致越权读文件（发送方本来就有该文件的读取权限）。
- 前端无新增 `innerHTML` 拼接，提示文案是常量 + 数字，无 XSS 面。
- 取消识别不涉及鉴权逻辑。

### 3.5 性能

- `clip.ReadFiles` 走既有专用剪贴板线程（`runClipboard`），最坏为 20×25ms 的
  `OpenClipboard` 重试，且在异步事件回调中执行，不阻塞渲染与 Enter 发送。
- 每次粘贴一次剪贴板读取（O(1) 次系统调用组），无轮询、无 N+1。
- 大文件投送仍走既有异步进度通道，粘贴路径没有引入同步 IO。
