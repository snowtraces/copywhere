## 1. Context（变更意图）

被控机为双屏时，主控光标移入后入口点总出现在被控**主屏左/右上角**，期望落在
"主控移入高度比例 = 被控主屏同比例高度"的位置。根因两处：

1. 入口绝对定位走 `input.InjectMoveAbs` → `SendInput` 绝对坐标，且把像素按**整块
   虚拟桌面**（双屏 3840×1080 甚至更宽）归一化；`MOUSEEVENTF_ABSOLUTE` 的折算基准
   （主屏 or 虚拟桌面）与多屏排列/缩放强相关，双屏下比例被拉偏 → 顶到角落。
2. 进程只声明 **System Aware** DPI。双屏不同缩放率时枚举坐标被 DPI 虚拟化、注入
   为物理坐标，两套坐标系错位 → 入口漂到角落。

上层"比例映射"本身正确，被底层注入方式带崩。

## 2. 五轴审查

### 正确性 — 通过
- `InjectMoveAbs` 改 `SetCursorPos`：与 `GetCursorPos`/`Monitors()` 同一套物理
  虚拟桌面像素坐标，精确且与屏数/缩放无关。控制期间移动仍走 `MoveRel`，不受影响。
- DPI 声明优先 Per-Monitor v2（`SetProcessDpiAwarenessContext(-4)`），失败退回
  `SetProcessDPIAware`；老系统/Win10<1703 仍可用。
- 主控端 `entryRatio` 改用"光标离场所属屏"高度计算比例，多屏主控也能正确映射。
- `ey >= Y+H` 钳到最后一行，防比例=1 越界。
- 负坐标副屏（x<0）边界用整数像素比较覆盖；多屏重叠时取首个命中，行为确定。

### 可读性 — 通过
- 注释解释"为什么"（SendInput 折算基准错位、PMv2 统一坐标系），符合项目中文
  注释风格；函数 `entryRatio` 职责单一、命名清晰。

### 架构 — 通过
- 复用 `Injector` 接口，未新增耦合；`entryRatio` 调 `currentMonitors()`（monsMu），
  调用点已释放 `s.mu`，无死锁风险（沿用既有独立锁模式）。

### 安全 — 通过
- 未触碰鉴权/token/网络面；无外部输入新增解析。

### 性能 — 通过
- `SetCursorPos` 单次调用，热路径无额外开销；`entryRatio` 仅在切换瞬间跑一次。
