## 二、本次已修复（发布前处理）

按用户确认的范围修复 5 项关键问题（另附 1 项同族的一行竞态修复）：

1. **数据竞争：被控端入口避让在锁外读运行期可变配置**（`internal/kvm/kvm.go:878`）
   `handleSlaveConn` 处理 `enter` 时锁外读 `s.cfg.EdgeDeadZone`，而面板滑块经
   `SetEdgeDeadZone` 在锁内写同一字段，两者天然并发。新增 `currentEdgeDeadZone()`
   （与既有 `currentMoveInterval` 同构）在锁内读，改为调用它。
2. **关闭右键菜单开关时半注册项清不掉**（`internal/app/shellsend.go:93`）
   原实现用 `Installed("")`（要求 `*` 与 `Directory` 两个 target 都在）作为清理守卫；
   杀软在第二个键上拦截会留下半注册状态，用户从此关不掉菜单项。改为无条件调用幂等的
   `Uninstall()`，仅用 `Installed("")` 决定是否记"已移除"日志。
3. **全新机器首次启动不生成 gui.log**（`cmd/copywhere/guilog.go:31`）
   `~/.copywhere` 目录只在 `config.Save` 时创建，而首次双击时它还不存在 → `OpenFile`
   失败 → 恰好丢掉最需要诊断的那次启动，与 CHANGELOG「启动失败时日志不再是一片空白」
   相反。改为先 `MkdirAll` 再打开。
4. **doctor 输出未打码的面板访问令牌**（`cmd/copywhere/doctor.go`）
   `gui.log` 里 `控制面板: http://127.0.0.1:PORT/?key=<32hex>` 带的是仍然有效的令牌，
   而 doctor 打印日志尾行时原样输出；同一命令对地址文件却做了打码。新增
   `maskLogTokens` 对日志逐行打码，并把 `maskToken` 从「保留前 8 位」改为整体遮蔽
   （原先不足 8 位时还会原样返回整个令牌），同步更新/补充单元测试。
5. **端口监听失败一律误判为「被占用」**（`internal/app/portowner.go` / `app.go:259`）
   原先任何 bind 失败都构造 `PortInUseError`，且 `Error()` 丢掉底层错误、协议名重复
   （`tcp 端口 47831/tcp`）。现在只有 `WSAEADDRINUSE`（10048）才归因为端口占用
   （其余原样带出系统错误），结构体补 `Role`（传输/发现），文案恢复
   `传输端口 47831/tcp 被占用：占用者 xxx (PID n)` 并附系统错误原文。
6. （同族一行修复）`internal/webui/server.go:511` 与 `cmd/copywhere/main.go:247`
   两处把 `cfg.ShellMenuOn()` 的求值挪到 goroutine 之外：超时回滚会改写配置，
   在 goroutine 内读既构成数据竞争，语义也错（要注册的是用户请求的状态）。

修复后门禁：`go build ./...`、`go vet -unsafeptr=false ./...`、`gofmt -l .`（空）、
`go test ./...`、`go test -race ./internal/kvm/ ./internal/webui/ ./internal/app/ ./internal/shellmenu/` 全部通过。

## 三、未修复项（记录在案，建议 0.5.1 处理）

### Important

1. **`/api/send-paths` 静默丢弃无效路径**（`internal/webui/server.go:649`）
   `os.Stat` 失败的路径被 `continue` 跳过，只要还剩一条就回 `200 {"ok":true}`，
   helper 只判状态码、不解析 `count` →「选 5 个只发出 1 个」与「5 个全成功」在用户侧
   完全等价。建议响应带 `requested`/`skipped`，helper 在 `count < requested` 时提示。
2. **多选失败会弹 N 个模态框**（`cmd/copywhere/main.go:469-490`）
   资源管理器多选是每项唤起一次 helper，失败路径每次都弹 MessageBox：未启动、无节点、
   未配对时选中 20 个文件 = 20 个弹窗。建议用命名互斥做提示节流，或只在「连不上面板」
   这一条路径弹窗。
3. **doctor 的「只读」语义有两处不成立**
   - `config.Load` 在文件不存在时会创建配置（`doctor.go:29` 注释称"全程不改状态"）；
   - 单实例锁是会话级的（`Local\`），别的会话/权限下的实例会被断言成"没有实例在运行"，
     且 `if running` 会跳过整段面板连通性检查，给出与事实相反的结论（`doctor.go:83-100`）。
4. **`shellmenu.Current()` 只看第一个 target**（`internal/shellmenu/menu.go:127`）
   `for ... return` 首次迭代即返回，`Directory` 永远读不到，doctor 因此对半注册状态报
   「已注册并指向当前 exe」。
5. **gui.log 4MB 轮转在拿到单实例锁之前执行**（`guilog.go:32-37`）
   再次双击时若日志超限会删除运行中实例仍持有的文件（Windows 允许 share-delete），
   之后该实例的日志静默写进已删除文件；运行期也没有任何轮转。
6. **提权常驻时 `/api/send-paths` 放大令牌权限**（`internal/webui/server.go:636`）
   提权实例可被同用户普通进程要求读取自身读不到的文件并发给已配对节点，越过 UIPI
   完整性边界。建议提权时限制路径在用户目录内，或在 README 写明不建议提权常驻。
7. **`-config` 下 gui.log 路径基准不一致**（`guilog.go:31` vs `doctor.go:163`）
   gui 恒写默认目录，doctor 按配置目录找 → doctor 误报「gui 尚未成功启动过」。
8. **`PortInUseError` 的既有消费方未跟随变化**：`main.go:230` 的「端口被占用 → 打开既有
   实例面板」分支仍假设占用人是 copywhere，`panel_url.txt` 为崩溃残留时会打开死页面。

- `trayprobe.go:24-29`：`hwnd`/`visible` 字段与 `IsWindowVisible` 白做（未消费）；与 `portowner.go` 的进程名解析重复实现。
- `guilog.go`/`doctor.go:163`：为显示 10 行把整个 4MB 日志读进内存。
- `main.go:106` `case "shell-send"` 不可达；`main.go:141` `cmdInit` 日志与 `fmt.Printf` 重复输出；`main.go:479` `-h` 落进「没有收到文件」返回 2；`main.go:462` `shell -status` 打印的是「将注册的命令行」而非真实命令行。
- `main.go:172` `recover` 只覆盖主 goroutine；可用 `debug.SetCrashOutput` 覆盖运行时崩溃（CHANGELOG 承诺"崩溃堆栈写进日志"）。

- `shellmenu/menu.go:117`：`Installed` 用 `==` 比较命令行，大小写/短路径差异会导致每次启动重写注册表。

- `config.go:78`：`kvm_edge_dead_zone` 未在 `Load` 里归一化，与端口/TTL 等字段不一致。
- 面板滑块 `max="200"` 与后端允许 0~400 不一致（`index.html:824` vs `server.go:495`），动一次滑块会把 201~400 的配置静默降级。

- `panel.go:80`：读地址文件的任何错误都被映射成 `ErrPanelNotRunning`，权限/占用类错误被说成"没有在运行"。
- `kvm.go:1583` 注释写 `umovePushThreshold = 500`，实际为 280（`kvm.go:64` 的"8px"估算也不准）。
- `CHANGELOG.md:50` 多了一个 `'`；`CHANGELOG.md:45` 在 v0.5.0 小节里举了 `v0.5.1` 的 exe 名；`README.md:153` 与 172 行对 `shell-send -config` 口径不一。
- `POST /api/send-paths` 的请求/响应契约（400/409/500 语义、404 旧实例）只在 README 有散文描述，建议并入 `docs/protocol.md`。

立刻被运行中实例接管，回读得到空文本。已在基线提交 `29cca42` 的独立 `git worktree` 中
复现同样失败，故属**既有的环境相关缺陷，不是 0.5.0 引入**；`internal/clip` 包在本次改动中
未被修改。建议 0.5.1 让该用例在检测到运行中的 copywhere 实例时 Skip，或改用独立格式/
独立会话隔离。

## 五、结论

修复上述 6 项后可提交并发布 v0.5.0。剩余 Important 项（send-paths 部分失败语义、
多选弹窗风暴、doctor 只读性与会话级锁、提权路径限制、日志轮转时机）不影响本次发布的
核心功能，建议在 v0.5.1 一并处理，并把 `-race` 纳入发版门禁。
