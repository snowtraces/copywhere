## 变更概述

1. **接收子目录重构**：重名文件不再追加 " (n)" 改名——每次接收在接收目录下创建独立子目录 `<20060102-150405>-<发送方名>`（同秒冲突追加 `-2/-3`，`os.Mkdir` 排他创建保证并发安全），文件保留原始文件名。
2. **合成 zip 自动解包**：协议头新增 `bundle` 布尔字段；发送端因多文件/目录临时打包的 zip 携带 `bundle=true`，接收端自动解包到同一接收子目录并删除 zip 本体，剪贴板回贴解包结果（顶层目录或全部顶层条目）。用户亲手发送的单个 zip 不带标记，原样保留不误解包。向后兼容旧版本对端（无标记不解包）。

## 第一轮审查发现（初）

### Correctness

- **【必改】文件夹 bundle（单个顶层目录）解包后 UI 记录仍指向已被删除的 zip** — `onFileReceived` 中记录映射条件 `len(targets) > 1` 漏掉单顶层目录情形：`os.Stat(path)` 失败 → 记录 Size 恒 0；Detail 指向不存在的 zip → 面板「打开/所在目录」失效；记录 Name 显示 zip 名。**已修复**。
- **FYI→已修复**：`unpackZip` 删除 zip 的时机早于"解出内容为空"校验，与"解包失败保留原 zip"承诺矛盾。已改为先列条目判空、最后删 zip。
- **FYI**：zip 内条目与 zip 同名时 `os.Create` 会截断正被读取的 zip。极端边角（自家 bundleZip 不会产生），Windows 下共享冲突会使解包中止而非损坏，行为安全，留待后续加固。
- **FYI**：dup 分支实际不可达（每次接收独占新建空目录），`resolvePath` 保留作兜底防御，注释与协议文档已自洽说明。Optional：后续可简化。

### Readability

- **Nit→已修复**：`fmt.Errorf("zip 内没有可解出的内容")` 无格式参数 → `errors.New`。
- **Nit**：`extract := func() error {...}()` 立即闭包略绕，可保留。
- **Nit→已修复**：`sanitizeSegment` 的 `Trim(s, ". ")` 会把合法前导点文件名（`.gitignore`）改名 → 改为 `TrimRight`；同时把 `..` 判断移到 sanitize 之后，封死 `".. "` / `"..."` / `". ."` 伪装段（初版 raw 判断在前，理论上存在洗白窗口）。

### Architecture

- ✓ 解包逻辑放在 app 层（bundle.go），transport 保持"落盘+校验+回调"通用职责，`bundle` 作为不透明布尔透传，边界干净。
- ✓ `OnFile` 回调签名扩展为 `(sender, path, dup, bundle)`，包内调用点与测试全部同步。

### Security

- ✓ **zip-slip 防护经独立实证**：审查员将 `extractZipEntry`/`sanitizeSegment` 复制到独立程序实测，`..`、` ..`、`.. `、`. .` 均被剥光或拒绝，`../`、`..\`、绝对路径（`/` 前缀、含 `:`）、盘符、ADS（`file.txt:stream`）均不可穿越。
- **Optional**：未过滤 Windows 保留设备名（CON/NUL/COM1），现代 Win10/11 风险极低，备忘。
- **Optional**：无解压总量/条目数上限（zip-bomb）。传输受配对令牌门禁（半可信对端），可后续加累计写入上限（如 min(10×压缩大小, 32GB)）。
- **Optional**：解包中途失败会留下部分解出文件 + 原 zip 共存子目录，可先解临时名再 rename 保证原子性。

### Performance

- ✓ 无明显问题：流式解包、不阻塞传输应答、冲突循环有界。

### 文档一致性

- ✓ `docs/protocol.md`（bundle 字段、接收流程、§5）与实现逐条一致；README/CHANGELOG 同步，无遗留旧描述。
- ✓ 向后兼容：新→旧（旧端忽略未知字段，按旧行为保存 zip）；旧→新（无标记不解包）。
