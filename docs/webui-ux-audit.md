# copywhere WebUI 交互设计审计

> 审计对象：`internal/webui/static/index.html`（v0.3.0 后 Unreleased 版本）
> 范围：交互设计 / 信息架构 / 反馈闭环 / 可达性 / 一致性。仅审计，不含代码修改。

> **修复状态（2026-09，见 CHANGELOG「Unreleased」）**：本审计提出的绝大多数
> 高/中严重度问题已随后落地——H1/H2（文案与按钮对齐）、H3（接收方向进度气泡，
> `transport.Handlers` 新增 `OnProgress`）、H4（SSE 重连补拉 `/api/records`）、
> M1（增量渲染）、M2（日期分组 + 「↓ 回到最新」）、M4（清空记录统一确认）、
> M5（进度气泡代际）、M8（配对弹窗不响应 Esc + 设备坞「待确认」标记）、
> M9（统一确认弹窗替代原生 confirm）、M10（错误 toast 驻留 8s 且可关闭）；
> H5 仅落地上传 XHR abort，「指定单节点发送」与 M3（失败重发入口）、M6、L5、
> L8、L9、L11 仍未实现。低严重度已修：L1 部分（aria-label）、L2（Ctrl+1/2）、
> L3（textarea 多行）、L4（图片灯箱）、L6 部分（错误行着色、自动滚动回底）、
> L7 部分（节点名留空提示）、L10。本文其余内容保留审计时点的原始记录。

## 总体评价

骨架健康：工作台单屏范式、持久设备坞、对话式时间线 + 输入框、Ctrl+K 命令面板、
即时保存设置，符合现代局域网传输工具的心智模型。签名跳过重绘（dock/layout）、
贴底跟随滚动（翻历史不打扰）、上传→发送进度条接管等细节做得认真。

主要短板集中在四类：**反馈闭环缺口**（接收无进度、失败无重试入口、文案与行为不符）、
**聊天范式的常见配套缺失**（日期分组、回到底部、逐条明细）、**隐式行为**
（发送目标不可选、不可取消）与**可达性**（键盘/读屏基本不可用）。

## 高severity（误导或阻断任务完成）

### H1. Composer 占位符承诺了不存在的"暂存"
`applyState` 中无节点时 placeholder 为"当前无在线节点：输入文本暂存…"，
但回车后直接调 `/api/send-text` → 409 → toast「未发现在线节点」。文本并未暂存，
用户按提示"先存着"会得到失败提示。文案与行为不符，且失败 toast 出现 3.2s 即消失。
**建议**：改为如实文案（"无在线节点，回车将失败"）或实现真的暂存（草稿保留 + 上线补发提示）。

### H2. 顶栏「发送文本」按钮名不符实
点击后只是切换到工作台并聚焦输入框。按钮暗示"点击即可发送"，实际还要再输入。
隐式的空间切换也可能让用户意外离开当前视图。
**建议**：改名/改图标为"写消息"，或直接移除（composer 已常驻工作台）。

### H3. 接收方向没有任何进行中反馈
大文件接收期间，接收方面板毫无感知（无进度条、无提示），直到完成后记录突现。
用户无法预判磁盘占用、也无法提前知道有人在传什么。
**建议**：传输协议已有进度上报（发送端 sink），补接收端进度事件 + 时间线接收气泡。

### H4. SSE 断线重连后不补拉记录
`connect()` 的 onerror 只是 2s 后重开 EventSource。断线期间产生的文件/文本
记录不会补拉（`/api/records` 有数据但 UI 不刷新），消息静默丢失直到手动刷新页面。
**建议**：重连成功后重新拉一次 `/api/records`（与启动合并逻辑复用）。

### H5. 发送不可取消、目标不可选
- 文件上传/发送开始后无任何中止手段（无取消按钮，后端也无取消协议）。
- 所有发送固定"发往全部在线节点"，无法指定单节点；设备坞卡片上也没有发送入口。
大文件误投或只想发给一台设备时没有退路。
**建议**：至少给上传 XHR 加 abort；指定目标可在设备坞卡片加"发送到该节点"。

## 中severity（体验明显缺陷）

### M1. renderFeed 全量重建 DOM
每条 SSE `file` 事件都触发 `renderFeed()` 清空重建最多 300 条消息。副作用：
- 用户正在悬停（图标按钮）或选择文本时被打断；
- 图片缩略图重新发起 `/api/file` 请求（依赖缓存）；
- 高频复制时 CPU 浪费。
**建议**：新消息增量 `appendChild`，合并 ×N 时只更新对应行。

### M2. 聊天范式配套缺失
- **无"回到底部"按钮**：向上翻历史时新消息不跟随（设计正确），但也没有 ↓ 跳转入口 + 未读数，用户会漏看消息；
- **无日期分隔**：记录只有 `HH:MM:SS`，localStorage 跨天历史看起来像同一天；本地持久化 + 服务端合并的排序只是"追加序"，跨午夜后的时间戳排序会错乱（15:04 的旧记录排在次日 09:00 记录后面显示为正确追加序，但用户无从分辨日期）。
**建议**：加日期分隔条（需后端记录带日期或前端收到时补记完整时间戳）；贴底判断失效时显示"回到底部"悬浮按钮。

### M3. 失败消息无重试入口
失败记录仅有红色 pill + 一次性 toast。后端虽有 5 分钟自动重试队列，但：
- 用户看不到"正在重试"状态；
- 超时放弃后无法手动重发。
**建议**：失败记录上加"重发"图标（复用 detail/文件路径）。

### M4. 清空记录无确认、不可撤销
`feedClear` 一键清除内存 + localStorage 全部历史。destructive 操作建议
confirm 或"已清空 · 撤销"toast（数据就在内存里，撤销成本极低）。

### M5. 进度气泡的边界 bug
`applyProgress` 完成态用 2500ms 定时器移除气泡并 `xfers.delete(key)`。
若同名同对端的新传输在定时器到期前开始，会复用同一 key 的气泡条目，
旧定时器触发时会把**新**传输的进度条删掉。同类：`pendingUpload` 接管逻辑
在"同名文件连续上传两次"时也可能串条目。
**建议**：气泡对象带代际 token，定时器只删除自己那一代。

### M6. 重复 copy 合并掩盖中间态
去重只对比末条：A→B→A 复制会产生两条 A；合并时直接覆盖 `time/status`，
同名同大小但**内容不同**的两次接收也会被合并（×2）。多数场景可接受，
但"×N"承载的语义并不精确，tooltip 也未说明合并规则。

### M7. 「已被拒」节点无出路
设备坞显示"已被拒"tag，但没有解释原因（对端解除了配对）和恢复动作指引，
用户只能靠猜。卡片上也没有"删除/忽略该节点"。

### M8. 配对请求弹窗 Esc 即消失
Esc 关闭后请求仍在后端 pending，但面板上无任何"有待处理的配对请求"的
持续提示（badge/横幅），用户可能以为拒绝已经生效。
**建议**：Esc 视为"稍后处理"，设备坞对 pending 节点加高亮或横幅。

### M9. 解除配对用原生 confirm()
风格突兀、不可定制，且是全站唯一原生弹窗。与"清空记录"一同纳入统一确认交互。

### M10. toast 生存期固定 3.2s
错误信息（含后端 400 详情）也在 3.2s 后消失，长文本读不完，无"复制详情"。
错误类 toast 建议加长驻留或手动关闭。

## 低severity（打磨项）

- **L1 键盘/读屏**：除 Ctrl+K 外全键盘不可达（空间切换、消息操作、设备坞操作均无快捷键/焦点样式）；图标按钮只有 title 无 aria-label；模态无 focus trap，Tab 可穿透 scrim。
- **L2 空间切换无快捷键**：Ctrl+1/2 或 Ctrl+Tab 未定义，palette 可替代但成本高。
- **L3 composer 单行输入**：多行/长文本无法在输入框内换行（旧 textarea 弹窗已删）。可考虑 Shift+Enter 换行或自动增高。
- **L4 图片预览无灯箱**：点击缩略图直接调系统查看器，面板内无放大预览；缩略图 200px 对截图偏小。
- **L5 节点重名歧义**：KVM 邻居、去重键、图标首字母都按 name 匹配，两台同名设备会互相干扰（后端同构）。
- **L6 日志查看器**：无过滤/搜索/级别配色；"自动滚动"勾选后不会立即滚到底，需等下一条日志。
- **L7 阈值/节点名等输入**：空节点名静默忽略不提示；数字输入无即时校验（靠后端 400 + toast）。
- **L8 敏感文本残留**：文本消息内容（≤2000 字符）持久化在 localStorage，无隐私提示；"清空记录"可清但用户无感知。
- **L9 深色主题下错误态**：失败气泡依赖 3px 边框 + 红色 pill，色弱用户仅剩 pill 文本可辨。
- **L10 窄屏溢出**：极窄窗口下 bubble `min-width:150px` + fcard `min-width:210px` 可能横向溢出时间线。
- **L11 上传条文案**："正在发送到在线节点"兜底 15s 收起，若节点均未配对被跳过，用户不知道发送其实没发生（后端有日志，面板无提示）。

## 做得好的（保持）

- 签名 diff 跳过 dock/layout 重绘，周期快照不打断拖拽/悬停；
- 时间线贴底跟随 + reduced-motion 全局降级；
- 上传条被发送进度接管的防重复设计（含 pendingUpload 兜底收起）；
- 设置"即时保存"心智一致，hint 文案普遍解释了生效时机；
- 图片预览端点的安全边界（仅接收目录 + 扩展名白名单）与 onerror 回退卡片；
- badge「无未读即隐藏」的不变式现在严格成立；
- 去重合并 + localStorage 持久化 + 启动时与服务端记录按 key 合并，避免刷新重复。

## 建议修改优先级（供排期参考）

1. H1/H2 文案与按钮行为对齐（几乎零成本）
2. H4 SSE 重连补拉记录（小改动，防静默丢消息）
3. M1 增量渲染 + M2 回到底部/日期分隔（聊天体验主体）
4. H3 接收进度（需后端配合，价值最大）
5. H5 取消发送/指定目标（涉及协议取舍，先做 XHR abort）
6. M3/M4/M5 失败重试、清空确认、进度代际 bug
