# copywhere GUI 方案规划

状态：已实现（2026-09）。M1~M4 全部落地：`copywhere gui` 子命令、系统托盘、
`internal/webui`（事件总线 + REST/SSE + 内嵌面板）、进度回调、暂停开关、
配置在线编辑、单实例互斥；`panel_url.txt` 落盘面板地址。
后续追加落地（超出原分期）：**配对认证**（peers.json 逐对独立令牌，面板配对/
解除，共享 token 认证废弃）、**KVM 布局跨机同步**（面板拖动配置，自动互为镜像）、
`web_port` 独立配置。
决策：**方案 A — 托盘 + 内嵌 Web 面板**；**与 TUI 共存，新增 `gui` 子命令**。

## 一、目标与原则

- 为 copywhere 提供图形界面：系统托盘常驻 + 浏览器打开的本地控制面板。
- 不破坏现有构建体验：纯 Go、零 CGO、不引入 Node 工具链，仍然单 exe。
- GUI 是新增前端而非替换：`run`（TUI/`-plain`）原样保留。
- 面板信息架构继承 TUI 三页：日志 / 在线节点 / 文件记录。

## 二、技术选型

| 维度 | 结论 |
|---|---|
| 界面载体 | `embed` 内嵌静态 HTML/JS + 本地 HTTP 服务（REST + SSE） |
| 托盘 | `fyne.io/systray`（无 CGO）；不可用时自封装 `Shell_NotifyIcon`（`golang.org/x/sys/windows`，量很小） |
| 实时推送 | SSE（日志行、节点上下线、传输进度） |
| 通信 | 面板只监听 `127.0.0.1`；首次启动生成随机访问 token 校验请求 |

被否决的备选：Walk（库停更）、Wails（需 Node + WebView2 运行时）、Fyne（CGO/mingw 构建、体积大、观感非原生）。

## 三、架构与进程模型

```
copywhere gui
 ├─ app.Run(ctx, cfg, Options{GUI: true})   核心服务原样运行（发现/传输/剪贴板/KVM）
 ├─ 事件总线（ui.Hub 扩展）                  日志行 + 结构化事件(peer 上下线/传输进度/收发记录)
 ├─ HTTP server (127.0.0.1, 端口可配)        REST 操作 + SSE 推送 + embed 静态页
 └─ 托盘图标                                 菜单: 打开面板 / 手动发送 / 暂停同步 / 打开接收目录 / 退出
```

- GUI 与服务**同进程**：剪贴板监控与 KVM 输入钩子依赖前台进程语义，不拆后台服务，避免额外 IPC。
- 新增**单实例互斥锁**（命名 mutex），防止 `run` 与 `gui` 双实例抢剪贴板和端口。
- `app.Options` 增加 `GUI bool` 形态；`Hub` 从"日志行订阅"扩展为"日志 + 结构化事件"。
- 传输进度：在 `sendToPeer` 增加进度回调注入（当前无回调，需小改 transport 层）。

## 四、功能分期

### P0（MVP）
- 托盘图标 + 菜单：打开面板、退出。
- Web 面板三页只读：日志 / 在线节点 / 传输记录（SSE 实时刷新）。
- 顶部状态栏：本机节点名 / 在线节点数 / 同步开关。
- 暂停/恢复同步。

### P1
- 设置页：自动阈值、接收目录、端口的查看与修改
  （原计划含 token 编辑——共享 token 认证已废弃，改为「已配对设备」管理）。
- 手动发送：文件拖入网页 + 系统文件选择框（等价 `send` 命令，不受阈值限制）。
- 传输实时进度条。
- 记录页操作：打开文件 / 打开所在目录。
- 开机自启开关（写注册表 Run 项）。

### P2
- 剪贴板历史列表，点选回贴。
- KVM 会话状态展示与开关。
- WebView2 独立窗口替代浏览器（可选打包）。
- 深色主题。

## 五、里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1 事件层 | Hub → 结构化事件总线；进度回调注入；REST/SSE API | curl 验证各接口，纯后端无 UI |
| M2 托盘+只读面板 | 托盘菜单 + 三页只读展示（SSE） | 双机互联，面板实时看到节点与收发记录 |
| M3 操作能力 | 配置编辑、手动发送、暂停同步、打开接收目录 | 面板完成一次跨机手动发送 |
| M4 打磨 | 进度条、开机自启、单实例互斥、剪贴板历史(P2 起) | 全功能回归 + `go test ./...` 通过 |

## 六、风险与对策

- `getlantern/systray` 不活跃 → 用 `fyne.io/systray`；最坏情况自封装 Win32 托盘 API。
- 默认端口被占用 → 占用时改绑随机端口，托盘菜单"打开面板"始终用实际端口。
- 面板安全 → 仅监听回环 + 随机访问 token + 默认不写任何状态（所有写操作走确认）。
- 双实例冲突 → 命名互斥锁，第二实例启动时直接唤起已有实例的面板。
